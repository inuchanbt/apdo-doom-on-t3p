# V47 / V48：前の画面のDMA送信と次の描画を重ねる

2026-11-05作成・実機結果反映。**両版が計測を完走し、V48の平均フレーム時間が約32.56％短縮。**

V46では開始地点の平均フレーム時間が205 ms、送信区間が99 msだった。
全無圧縮化で空いたRAMを使い、CPUの描画とLCDへの転送を重ねる。
今回も120×120の色インデックス画像を240×240へ拡大する。画像の詳細度はV46と同じ。

## 比較する2版

- **V47：直列の比較版。** 新しい転送処理で1枚を最後まで送り、次の描画へ進む。
- **V48：並行転送版。** 送信を開始したら次の描画へ進み、描画・アセット読取りの合間に転送を進める。
  次の画面を送る前には、前の画面が最後まで送られたことを確認する。

両版のデータ、2枚の画面バッファ、色変換、16列単位の転送、クロック設定は共通。
V46の4列転送と列ごとの色変換も変更されるため、並行化の効果は**V47とV48で比較する**。

120×120の画面を2枚（28,800 B）、送信中の画面専用パレット（512 B）、
16×240ピクセルのRGB565バッファを2本（15,360 B）持つ。
送信中のバッファは完了するまで書き換えず、空いている方で次の16列を生成する。
パレットも画面に固定し、次のフレームの発射・ダメージ表現で前の画面の色が変わらないようにする。
確定した画像を次の描画面へコピーし、HUDやメニューの部分更新を維持する。

割込みや第2コアは使わず、描画・読取りと、描画を省いたメニューのループから処理を進める。
既存DBI DMAの完了フラグ `cf_task_done` とタイムアウトを使い、失敗後は転送を再開しない。
16列の実機動作と並行転送は、開始地点の固定40 ticの試験を完走した。通常プレイや長時間の安定性は未確認。

## 実機結果

ユーザーの2枚の写真から、V47の版表示 `2F`、V48の `30`、両版の測定数 `1E`、
完了 `D00E`、最終tic `28`、照合値 `EBC8D404` を確認した。停止は故障ではなく計測完了の仕様。

| 項目 | V47・直列 | V48・並行 |
|---|---:|---:|
| 平均フレーム時間・4行目 | `D7` = 215 ms | `91` = 145 ms |
| DEFLATE時間・7〜9行目 | 0 ms | 0 ms |
| 平均時間の逆数 | 約4.65フレーム／秒 | 約6.90フレーム／秒 |
| 測定数／最終tic／照合値 | 30／40／`EBC8D404` | 同じ |

**70 ms、約32.56％の短縮。平均時間の逆数では約1.48倍。** 同じ画像列・データ・転送方式の対照比較で、
描画と送信を重ねる効果を確認した。ブリッジ以外の12個のネイティブオブジェクトはバイト単位で一致する。
最短／最長とpresent呼出し時間は、この平均フレーム時間中心の記録では転記していない。

各版1回、入力なし・固定tic・開始地点の結果。通常プレイ全般のFPS、入力から表示までの遅延、
移動時の負荷や長時間の安定性までは確認していない。重なる処理を単純に足し引きして描画時間や転送時間へ分離もしない。
V46からは計測位置と転送単位も変わるため、今回の並行化の効果はV47対V48で評価する。
次の開発ではV48の方式を採用し、V47を比較用として残す。

[写真のハッシュ・転記値・計算結果](../analysis/native-doom-v47-v48-benchmark.json)。

## 実機での手順

1. **V47 → V48**の順に書き込み、各版を通常起動してボタンを押さずに待つ。
2. 10フレーム準備＋30フレーム測定の後、左上に全14行が表示され、`D00E`で停止する。
   **途中の数値表示は出さない**。入力無効と最後の停止は計測版の仕様。
3. 各版の全14行を撮影する。

| 行 | 内容 | V47の期待値 | V48の期待値 |
|---|---|---|---|
| 1 | 版、16進 | `0000002F` | `00000030` |
| 2 | 測定フレーム数 | `0000001E` | `0000001E` |
| 3 | 完了 | `0000D00E` | `0000D00E` |
| 4〜6 | フレーム全体：平均／最短／最長、ms | 実測待ち | 実測待ち |
| 7〜9 | DEFLATE：平均／最短／最長、ms | すべて0 | すべて0 |
| 10〜12 | present呼出し：平均／最短／最長、ms | 実測待ち | 実測待ち |
| 13 | 最終tic | `00000028` | `00000028` |
| 14 | 画像列の照合値 | `EBC8D404` | `EBC8D404` |

主に比較する値は**4行目の全体平均**。10〜12行目は、画面確定時の待ち・準備と最後の転送待ちの時間で、
背景で進んだ転送全体の所要時間ではない。従来の「送信時間99 ms」と同じ意味ではない。

DMAへ計測外の処理時間を与えないよう、画像列の照合計算を両版とも測定区間に含める。
準備の最後の転送を測定開始前に待ち、40枚目の転送も最後の測定区間で待つ。
途中の診断表示がDMAを使うことも避ける。このためV46の205 msと単純比較はせず、新しい2版を対照とする。
固定1フレーム1 tic・入力なしの開始地点試験であり、通常プレイ全般のFPSとは区別する。

## 容量と検証

| 項目 | V47 | V48 |
|---|---:|---:|
| ゲームパック、全582ページ無圧縮 | 1,199,344 B | 1,199,344 B |
| 更新ファイル | 1,540,096 B | 1,540,096 B |
| 静的RAM | 114,060 B | 114,060 B |
| 予約後のRAM残量 | 54,752 B | 54,752 B |
| 予約後のFlash残量 | 54,240 B | 54,240 B |

V46比の静的RAM増加は26,400 B。Flashドライバー80 KiB、RAMドライバー32 KiB、
スタック16 KiB、ROM／IRQと上部512 Bの更新領域の予約を維持する。
CPU／PLL／FlashクロックとDBI分周設定はV46から変更せず、実周波数も今回測っていない。

- 転送を遅らせるC試験336画面で、バッファ保持・色変換・2倍拡大・画面順序・パレット変更・HUD保持を検査。
  送信／ポーリング／完了待ちの失敗も検査する。
- 実際のMMIO操作コードを模擬レジスターで検査。16列の寸法、転送元、完了フラグ、ビジー時の即時復帰、
  完了待ちとタイムアウト時の出力停止を確認。
- 実エンジンをV46参照版・V47相当・V48相当で各148ステップ実行。
  発射・前進・旋回・メニューまで色インデックス、RGB565画像とゲーム状態が一致する。
  各新方式は146画面を完了し、送信元保持を8,760回検査。描画のないメニューフレームも通す。
- 従来の表示／MMIO／固定tic検査とPython回帰テスト66件が通過。
- 別の展開ツールで更新ファイルを検査。app.binはペイロードと一致し、他の44ファイルと2ディレクトリーは純正と一致。
  作成時に先頭20 KiB・リソース末尾・入れ子CRCも確認する。

PCの遅延転送はバッファの寿命を検査する模擬動作であり、実機の速度を予測するものではない。
通常プレイの実機基準は引き続きV30、直前の計測基準はV46として残す。
