# V33 / V34：固定条件での30フレーム比較

V33はV30と同じDEFLATE／無圧縮のゲームパック、V34はV32と同じ
LZ4混在パックを使う。展開用ハフマンテーブルは両方7ビット、ページ
キャッシュ35枚、描画・DBI設定も共通。

今回はエンジンの既存の `singletics` を有効にし、ゲームは描画1回に
つき1 ticだけ進める。エンジン向け時計も描画回数に基づく35 Hz相当の
論理時計にする。ドライバーの `km_millis()` は実時間のままなので、
フレーム・展開・送信に要した実時間は独立して測れる。

10フレームのウォームアップ後、11〜40フレーム目の30回を測る。
発射入力は無効。終了時は結果を残すため意図的に停止する。
最初の10回で計測値が0、ボタンが効かない、最後に停止するのは仕様。

## 操作

1. V33を書き込み、ボタンを押さずに通常起動する。
2. 左上の3行目が `0000D00E` になって停止したら、診断値全体の写真を1枚撮る。
3. V34も同じ操作をし、終了画面を1枚撮る。

可能なら各版を再起動して複数回繰り返すと、ばらつきも比較できる。
常用時はV30またはV32のプレイ用ファームへ戻す。

## 終了時の表示

数値は16進数。時間の単位はms。行番号は上から1始まり。

| 行 | 内容 |
|---|---|
| 1 | リビジョン：V33=`00000021`、V34=`00000022` |
| 2 | 測定回数：`0000001E`（30） |
| 3 | 完了：`0000D00E` |
| 4〜6 | フレーム時間の平均・最短・最長 |
| 7〜9 | DEFLATE＋LZ4展開時間の平均・最短・最長 |
| 10〜12 | 最初の帯の送信から最後のDMA完了までの平均・最短・最長 |
| 13 | 最終ゲームtic：`00000028`（40）を想定 |
| 14 | 測定した30枚の色インデックス画像に対する照合値 |

13行目と14行目が両版で一致するかを確認し、その後に速度を比較する。
照合値は画像列を順にFNV-1aへ入力したもの。照合処理は計測区間の
後に行い、ゲームの論理時計にも反映しない。暗号学的な完全一致の証明ではない。

## 評価範囲

開始地点で、入力なし・1 tic／フレームという制御された負荷の比較。
通常プレイの可変tic処理や発射時の負荷とは異なるため、V28／V29の
以前の平均値や、通常プレイ写真の単発値とは直接比較しない。
この結果だけで移動・戦闘中や他の場所のフレームレートを保証しない。

エンジンのスケジューラー自体のPC検査は
`python scripts/check_benchmark_tics.py --compiler <host-clang>` で実行できる。

## 実機結果（2026-11-05）

ユーザー提供の終了写真から転記。両方とも30回完了、最終ticは40、
画像列の照合値は `C269CBCE` で一致した。終了時の停止は仕様どおり。

| 実時間（ms） | V33：従来パック | V34：混在パック |
|---|---:|---:|
| フレーム 平均／最短／最長 | 668 / 640 / 736 | 640 / 579 / 753 |
| 展開 平均／最短／最長 | 427 / 398 / 483 | 443 / 430 / 501 |
| 送信 平均／最短／最長 | 83 / 83 / 84 | 83 / 83 / 84 |

平均フレーム時間は4.2%短縮したが、展開時間は16 ms増えた。
展開以外の時間差は約44 msで、この表示だけでは読取り・無圧縮コピー・
CRC・描画などのどこが短縮したかは分からない。送信時間は変化なし。
各版1回の結果なので、再現性や最悪時間の改善はまだ確認できない。
通常プレイの基準版はV30とし、混在方式の小幅な効果を示す結果として扱う。

全14行の16進値、ファームと写真のSHA-256、評価上の制限は
[結果JSON](../analysis/native-doom-v33-v34-benchmark.json) に記録した。
