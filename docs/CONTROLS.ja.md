# T3Pの操作

## V58

通常起動では黒背景にFreedoomのバナーが出て、そのままE1M1が始まる。
USB-Cオス端子を上に向けて普段の持ち方で起動し、ゲーム画面が出たら約1秒静止する。
加速度計の安定した8サンプルを基準に中立姿勢を取る。

| 入力 | ゲーム中 | メニュー中 |
| --- | --- | --- |
| 左ボタン | 短押しで発射、長押しで連射 | 決定 |
| 右ボタン | 扉やスイッチを使う | 戻る |
| 両ボタンを700 ms長押し | メニューを開く | メニューを閉じる |
| タッチしてドラッグ | 移動・旋回 | 上下で項目を選択 |
| 左右・前後に傾ける | 左右旋回・前進と後退 | 入力休止 |
| 手拍子 | 1回で1発 | 入力休止 |

タッチ中はタッチ移動を優先する。傾きは中立からの成分が重力の300/1024で入力を開始し、200/1024で止める。
中立軸からの単純な傾きなら、それぞれ約17°と11°が目安になる。
左に傾けると左を向くようにセンサーのX軸の符号を調整した。

マイクは起動後の約1秒で周囲の音量に合わせる。音を検出した後は静かになってから次を受け付ける。
射撃は35 ms、被弾は65 ms振動し、両方が重なる場合は被弾を優先する。
モーター駆動中と直後のマイク入力は捨てる。実機では手拍子1回で1発、発射と被弾の振動の違い、
モーターによる誤発射が起きないことを確認した。

## UAC環境モニター

両ボタンを700 ms長押ししてメニューを開き、上下のタッチドラッグで `UAC MONITOR` を選ぶ。
左ボタンで開き、右ボタンでメインメニューに戻る。
起動後の最初の8有効サンプルを基準に、気圧をhPa、相対高度をmで表示する。
平滑化後の相対高度が+3 m以上の状態が約2秒続くと `UPPER DECK FOUND` が表示される。
圧力補正、基準値の取得、高度判定はPCの模擬データで確認した。実機の気圧精度と上昇判定は未計測。

## センサー診断

右ボタンを押したまま通電すると、センサー診断に入る。上から順に16進数で表示する。

1. バージョン（V58は `0000003A`）
2. 加速度計の状態（0は初期化失敗、1は読取り待ち、2は中立調整中、3は調整済み）
3. X軸（符号付き）
4. Y軸（符号付き）
5. Z軸（符号付き）
6. マイクの最大振幅
7. 現在の発射閾値
8. 最大振幅を記録したブロックで音が強かった区間数
9. 発射判定回数
10. 振動用PWMの準備状態（0は未準備、1は準備済み）

左ボタンでマイクの最大値と判定回数を消去する。
ボタンを押さずに電源を入れ直すとゲームに戻る。

## 初期のPC上の入力試作

`native/t3p_input.c`は機器から独立した入力処理。実機側との接続前に仮データで検査した。
この段階では、センサーは設定済みという前提で生値の読取りを試作した。

| 入力 | 試作した割当て |
| --- | --- |
| 左右に傾ける | 左右旋回。中立位置の校正と画面方向に合わせた軸変換は実機接続時に追加 |
| 前後に傾ける | 前進・後退 |
| ボタン1 | 射撃。メニューでは決定 |
| ボタン2 | 扉などを使う。メニューでは戻る |
| 2ボタン同時に700ms | メニュー。押し続けても1回だけ |
| タッチ左側 | 方向操作。触った軸では傾き操作より優先 |
| タッチ右上／右下 | 射撃／使う。メニューでは決定／戻る |
| タッチ最上部 | 左端はメニュー、残りは武器1〜7の直接選択 |

タッチ座標は仮想0〜1023を使用し、物理解像度に依存させていない。
物理座標からの変換、表示する操作目印、感度、持ち方は実パネルに合わせて調整する。
傾きには平滑化と、動き始め／止まりで閾値を変える処理を入れた。
メニューでは傾きを無効にし、開いた瞬間の意図しない選択移動を避ける。
ボタン／タッチ／傾きの読取り失敗時は該当validを必ず落とす契約にしている。
入力処理はvalidが落ちたとき、前の押下や移動を保持しない。
変換はゲームの入力更新単位で一度行い、結果を保持する。
診断用の状態取得から変換を呼んで、長押しの単発イベントを消費しない。

初期試作で解釈したセンサー値は、タッチ12bit座標、加速度の符号付き12bit、BMP280互換の20bit ADC値。

同じ入力コードをPC版の実際のDOOMへ接続した検査でも、傾きの移動・旋回、
射撃、2ボタンのメニュー操作は通った。メニュー中は傾きでプレイヤーが動かないことも確認した。
