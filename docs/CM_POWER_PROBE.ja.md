# 電源エッジ基準のCM補助プログラム

2026-11-02。別ソース `recovery/cm_power_probe`、識別名 `t3p_cm_power_probe` v1。
ビルドとオフライン検証済み。**CMへインストールし待機状態を確認。実機のADC接続・波形・T3P動作は未検証**。
既存 `cm_rom_probe` v3とその制御スクリプトは変更していない。

## 入力と待機

- GPIO26/ADC0：T3P側VBUS→10kΩ→GPIO26→10kΩ→共通GND。
  GPIOへつなぐ前に中点電圧をDMMで確認する。5Vを直接入力しない。
  メーカーCM回路図はGPIO26をP1.12とU3.40にのみ結線し、SDKもRP2350AのADC0=GPIO26を定義。
- GPIO10→実測5.098kΩ→D+：確認済みの別バイアス経路。上記10kΩ2本と混同しない。
- D+=GPIO13（時計）、D−=GPIO12（データ）。固定0x16ef、PIO波形は既測定の共通ソース。
- 初期状態ではGPIO10/12/13の出力とプルを無効化。GPIO26はADC入力のみ。
  自動USBホスト開始や自動キー送信はない。

## 操作条件

`scripts/cm_power_probe.py` は引数なしの動作指定では状態読み取りのみ。
実行時には常に `--output` を指定する。正確な識別名・ピン・時計・遅延値を確認し、
未知のプログラム、使用済み状態、確認不足、想定外のADC値では操作を拒否する。
短いコマンド書込みや機器側の拒否を再試行しない。

`--action adc-on` はT3Pなしで電源ON時ADCを確認する。
`--action adc-off` はその後、電源OFFを確認する。OFF値が100ms以上続くことを要求。
どちらも波形を出さない。`--action bias` はT3Pなし・電源ONで抵抗経路を確認する。
電源確認とバイアス確認はhelperの再起動で失われるため、毎回実施する。

`--action host` は電源ONで通常USBの記述子確認だけを開始し、この起動中の試行を消費する。
`--action bench` はT3Pを物理的に外して固定キー1回と後段の動作を検証する。
これらの後に同じhelper起動でキー試験を再実行しない。

`--action check-arm` は電源OFFで待機して直ちに解除し、出力がなかったことを確認する。
`--action arm --seconds 610` は電源OFFで600秒待機し、最初の電源立上りに対し一回だけ送信する。
待機中もD+/D−のプルとバイアスは無効。CDC切断の検出で待機解除。
最初のエッジで試行を消費し、電源低下でも再送しない。
送信前・送信直後・応答観測中の電源低下ではUSBホストを開始しない。
観測終了後のUSBホスト動作中に電源ジャンパを操作する手順はまだ用意していない。

ADC閾値は基準3.3V・1:1分圧を仮定した検出用値。
OFF<=約0.5V、ON>=約4V、その後の維持>=約3.5V。
立上り後100µs待ってから送信処理へ進むが、これは探索用の初期値であり、
T3PのROM受付時刻として実証した値ではない。
ADCの取得間隔とPIO有効化までの実遅延を記録し、最初の時計エッジはスコープで確認する。
連続Highの要件はサンプルに対する判定であり、サンプル間の短い変動まで証明しない。

応答は抵抗による既知バイアス下のLow候補として記録するだけで、ROM ACKと断定しない。
標準USBの記述子だけを読む。HID設定・MSC/SCSI・RAMローダー・Flash操作は実装しない。

## 三本のプローブ配線後の確認と停止

ユーザーがCH3まで配線した写真を送付。PC側の状態は電源OFF、送信0、各確認フラグは再起動で消失。
この時点でSCPI接続は復帰しており、原因・再起動の有無は断定しない。
CH1/2/3の10倍・DC・1MΩとCH3の1V立上りトリガーを設定・照合した。
写真ではVCCジャンパが外れていたため、ユーザーに戻すよう依頼し、完了報告を受領。
ADC_ON_CHECKを再実行し3084～3100で成功。

T3PなしでCH2立上り1.5VのSINGLE待機後、BIAS_CHECKを1回実施。
High確認は成功したが、解除後のLow確認が失敗。GPIO10の出力解除読み返しは成功。
`local/cm-power-bias-check-first.json`：high_seen=true、low_seen=false、bias_released=true、passed=false。
キー波形・USBホスト開始は行っておらず、frames=0を維持。

スコープはWAITのままで確認パルスを捕捉していなかった。
公式MHO900 Programming Guide PDF35ページ（本文11ページ）の:TFORceを用いて、
パルス終了後の現在電圧だけを強制取得。最初のCH1は全点が上限飽和していた。
CH1のレンジを20V/div、offset=0へ広げ、再度強制取得した。
CH2は約0V、CH3は約2.5V、CH1は表示約5V。詳細はanalysis/cm-power-bias-first-diagnostic.json。
これらは終了後の静止状態であり、確認パルス自体の記録ではない。
プローブの物理倍率はまだ独立確認しておらず、MCU端子へ実際に5Vがかかったと断定しない。
現在スコープはSTOP、CH1は診断用20V/divのまま。次の正常波形試験前に戻す。

ユーザーへPCケーブルを抜き、抵抗レンジでCM10→黒USB+、黒VBUS→USB+、黒VBUS→USB−を測るよう依頼。
前者は約5.1kΩを想定。配線・接点・倍率を切り分け、確認が通るまで復旧キー送信へ進めない。

ユーザーは回路配線は正しく、外れやすいプローブを戻す際に測定点がずれたと説明。
抵抗3点の依頼はいったん保留し、PCを抜いてCH1 USB−／CH2 USB+／CH3中点へ
接触点を戻してPCへ戻すよう会話本文で案内した。質問ツールの内容が履歴に残らないと
ユーザーが報告したため、今後の物理操作指示は会話本文にも必ず記す。

修正写真F4A4FF61を受領。スコープを通常範囲へ戻したが、ADC_ON_CHECK再試行は
CMのCDC候補が見つからず、コマンド送信前に終了。
シリアルとPresentOnly PnP一覧にもCAFE/2E8A機器は見つからなかった。
原因は未確定であり、ケーブル故障やCM故障とは断定しない。
スコープはSTOP、CH1/2=1V/div、CH2立上り1.5V、CH3は10倍DC1MΩの設定を維持。
ユーザーへプローブを動かさずCMケーブルのPC側だけをつなぎ直すよう案内。
この修正写真受領後、新しいバイアス確認パルスもキーも送っていない。

PC側の抜き差し完了後、CM認識が復帰。ADC_ON_CHECKは3087～3099で成功。
BIAS_CHECKもHigh・Low・出力解除すべて成功したが、CH2トリガーは捕捉しなかった。
プローブを動かさずCH1トリガーに変更し、理由のある診断再試行を1回行った。
再試行も成功し、CH1に約2.001456msのD+パルスを捕捉。
前0.005V、高3.019V、後0.024V、CH2に1.5V超のサンプルなし、CH3中点中央値2.561V。
全チャンネル飽和なし。解析はanalysis/cm-power-bias-fixed.json、図はartifacts/cm-wave-scope/cm-power-bias-fixed.png。

現在の接触点を維持し、以後はCH1=D+クロック、CH2=D−データ候補、CH3=分圧中点として扱う。
CH2がD−データである最終確認は、次の固定キー16ビット復号で行う。
解析スクリプトは --clock-channel 1 --data-channel 2 を明示指定できるようにした。
古い既定値CH1データ・CH2クロックは従来記録用に維持。ファームのGPIO13/12の定義は変更していない。
確認パルスの回数はキー送信回数に数えない。現在も新helperでframes=0、ホスト停止。
スコープはCH3立上り1V、0.5ms/divへ準備済みだがSTOPのまま。
次にVCCジャンパのみを外してADC_OFFと待機解除検証を行ってから、T3Pなしの一回送信試験へ進む。

ユーザーがVCCを外したと返信し、ADC_OFF_CHECKは10～21で成功。
check-armはARM直後DISARMでframes=0、未使用、ホスト停止を確認した。
記録：local/cm-power-adc-off-before-bench1.json、local/cm-power-check-arm-before-bench1.json。

PC側に明示的なpower-bench動作を追加。ARM_POWER_ONCEを1回だけ送り、
電源エッジ1件・正常キー1件・実遅延記録・バイアス解除・ホスト開始まで確認して終了する。
T3Pがないため機器の列挙待ちは不要。操作条件とエッジ数の検証を含む10テストが成功。
ファームは変更・再書込みしていない。

スコープをCH3立上りのSINGLE待機、CMを600秒のpower-bench待機へ入れた。
記録local/cm-power-bench1.json、実行セッション47592がCDCを保持。
この待機中に別のシリアル読取りを開かない。データ・状態は継続保存されるJSONから確認する。
ユーザーへT3Pを外したままVCCジャンパだけ戻すよう案内。待機確認時点ではframes=0。
最初の数秒で最大サンプル間隔185µsを観測したため、100µsという設定を正確な外部遅延とは扱わない。

## 電源試験2の記録と通常USBの確認待ち

ユーザーはVCCを戻す際にCH2が外れ、現在は戻したと報告。戻した場所をUSB+と説明した。
接触が外れた時刻は不明として記録し、追加送信せず元波形を保存した。
v2は正常に一回送信、FIFO不足なし、PIO出力解除を確認。バイアスは終了時HighでLow候補なし、
解除後に通常USBホストを開始。セッション36392は成功で終了した。

中点2.0Vの立上りから最初の時計まで248.144µs。ソフト内部ADCエッジ→PIO有効化は231µs。

バイアス中中央値3.331V、解除後約0.031V。中点は約2.552V。
analysis/cm-power-bench2-wave.json、artifacts/cm-wave-scope/cm-power-bench2-wave.png。
