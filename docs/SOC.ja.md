# T3PのSoC・メモリ調査

2026-11-01更新。接続中の本体は純正3.0.2、アドレスを使う静的解析は配布3.0.3。
T3PのAC707N系という判定と、同系統AC7076Aの資料上の仕様を分けて記録する。
本体の刻印、実クロック、RAMテスト、FlashのJEDEC IDはまだ取得していない。

## 追加の型番情報

2026-11-01、ユーザーから「T3Pを分解した人によるとAC7076A6」との情報を受領。
これは分解報告の伝聞であり、接続中の個体の刻印をこちらが撮影・確認した結果ではない。
参照URLや刻印写真は未受領。

取得済みJieLi AC7076A Datasheet v1.3の本文19ページ（PDF20ページ）
「IC Marking Information」を画像で再確認した。

- 末尾のFlash容量コード`6`は16Mbit。バイト換算で2MiB（2,097,152バイト）。
- 内蔵PSRAM容量はさらに追加する末尾記号で表し、記号なしは内蔵PSRAMなし、
  `S`は16Mbit、`T`は64Mbit。
- したがって報告どおりの完全な型番が`AC7076A6`なら、型番上は内蔵Flash 2MiB、
  内蔵PSRAMなしの構成。基板上の外付けRAMの有無までこの刻印規則だけで決めない。
- 2MiBという容量は配布ファームの終端配置と整合するが、実機のFlash ID読取りはまだ未実施。

288MHz、主SRAM＋キャッシュ284KiB、別センサーハブSRAM32KiBという同系統の仕様は
以下の資料と整合する。型番情報が増えても、実クロックの測定値や使用可能RAMが
そのまま増えたことにはしない。

## メーカー資料で確認した同系統の仕様

JieLi作成「AC7076A Datasheet」v1.3、2025-09-30、本文3〜5ページ。
[入手元PDF](https://www.yunthinker.com/static/upload/file/20260112/1768212647955698.pdf)
は販売代理店のミラー。保存したPDFのSHA-256は
`72647ef88adcaf8bced9e90408878e38c27652317e959ee30cdc7847ea2e4c9d`。
画像化されたFeaturesページを目視照合した。

| 項目 | AC7076A資料の仕様 | T3Pでの扱い |
| --- | --- | --- |
| 主CPU | 32bit Dual-Issue DSP、288MHz | AC707N系/pi32v2-r3は純正ファームとSDKから確認。細かな型番・実動作周波数は未確認 |
| 演算 | IEEE754単精度FPU、数学コプロセッサー | エンジンは主に整数演算。FPUがあるだけで高速化率は決まらない |
| SRAM | 284kbyte、I/Dキャッシュ | SDKの主RAM220KiB＋Iキャッシュ32KiB＋Dキャッシュ32KiBと整合 |
| センサーハブ | 別の32bit CPU、24MHz、SRAM32kbyte | メインCPU用の自由な追加ヒープには数えない |
| 描画 | 2.5D GPU、拡大縮小・回転・合成、JPEGデコード | DOOMの3D描画を自動で肩代わりするGPUではない。今回は未使用 |
| USB | Full Speed USB×1 | 実HIDの転送速度は未測定 |
| 内蔵Flash | 型番の構成に依存 | T3P配布ファイルの終端配置は2MiB構成を示唆。実容量の読取りは未了 |

Dual-Issueは命令の発行方式。主CPUが同じもの2個あるという意味ではない。
別CPUであるセンサーハブを含めても、DOOMを自動的に2コアへ分散できるわけではない。

## 純正3.0.3と公式SDKによる内訳

SDK固定リビジョンは`SOURCE_LOCK.json`参照。
`cpu/br35/maskrom_stubs.ld`の主RAM境界は`0x100000..0x137000`、225,280バイト＝220KiB。
`cpu/br35/sdk_ld.c`ではI/Dキャッシュを各4way×8KiBとして扱い、wayをRAMに転用できる。
**284KiBへさらにキャッシュ64KiBを足してはいけない。**
実際のアプリ領域からはROM用・割込み用・更新用領域などを差し引く。

純正の初期ヒープ範囲:

| 領域 | 範囲（終端を含まない） | バイト数 |
| --- | --- | ---: |
| 主RAM内 | 0x1233A0〜0x136E00 | 80,480 |
| Dキャッシュ転用部 | 0x374208〜0x378000 | 15,864 |
| Iキャッシュ転用部 | 0x3C4000〜0x3C8000 | 16,384 |

これは初期化時の範囲であり、起動後の空きメモリやDOOMがそのまま使える容量ではない。
センサーハブの32KiBは別領域。PSRAMという汎用文字列やMMUの仮想範囲だけで
T3PにPSRAMが載っているとは判断しない。

純正には128MHzと288MHzを条件で返す上限らしい関数と、288MHzを含む選択表がある。
288MHzの即値があることと、接続中の本体が288MHzで走っていることは別。
現在値は未測定。PLLの576MHz設定もそのままCPU周波数とは扱わない。

`scripts/soc_evidence.py`はアプリSHA-256、20か所の命令と実バイト、クロック表、
SDK領域定義を照合し、`analysis/soc-3.0.3.json`へ根拠を書き出す。
3.0.3のアドレスを接続中の3.0.2に対して呼び出すことはしない。

## DOOMへの見通し

表示出力を追加する前の検査ELFは静的RAM85,522バイト。
320×320 RGB565の全画面バッファ1枚だけでも204,800バイトになるため、
画面全体をメインRAMへ保持する構成は避け、列を小さくまとめて液晶へ送る。
キャッシュ転用領域やセンサーハブRAMを当てにせず、まず主RAM内で収める。
実際のフレームレートは、実機の起動・Flash読取り・描画を通して測定する必要がある。
