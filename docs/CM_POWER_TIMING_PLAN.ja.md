# 次の切り分け案: 電源投入とデータ接続の分離

2026-11-02。検討中で、追加配線・電源感知プログラム・次のキー試験は未実施。
第4回ではキー値と時間幅が実測一致し、既知バイアス下でもLow応答は得られなかった。
手でUSBを挿す方法ではVBUS・GND・D+/D−の接触時刻が独立に変化し得るため、
次はデータ線を接続済みにしてT3P側5Vだけを切り替える比較を行う。
起動タイミングが原因と確定したわけではない。

優先案は、データ線を維持したまま5Vだけを切れるUSBスイッチ付き延長。
ユーザーへ所有状況を質問中。電源専用製品でデータ線が欠ける場合は使えないので、
採用前に通常HID通信が通ることと、OFF時のT3P側電圧を測って確認する。

なければ、所有済みのYC269メス取り出し基板をCMのオスへ挿し、
新しいオス・メス取り出し基板のオスをT3Pへ挿す構成が候補。
新基板のメスとCMのオスを直接つながず、2枚のヘッダー間でGND・D+・D−を接続し、
5Vのみを別のスイッチまたは取り外せるジャンパ線で接続する。
CMはPCから常時給電、T3PだけをOFF/ONできるようにする。
YC269のA/B側USB2端子は独立の可能性があるため、使用ピン・向き・導通の確認が必要。
信号線は短くし、電源OFFの導通確認とT3Pなしの波形確認を先に行う。
この段落は配線指示ではなく案で、具体的ピン表はまだ確定していない。

既存5.098kΩのGPIO10→D+観測経路は維持する。
電源投入から送信までを測るには、CMでT3P側VBUSの立上りを感知する入力も必要。
候補は10kΩ2本の分圧で5Vを約2.5Vへ落とした入力。
GPIO/ADCの採用ピンは回路図・SDKで照合してから決定し、入力へ接続する前に
DMMで分圧電圧を確認する。5VをRP2350入力へ直接接続する構成にはしない。
データ線から無給電T3Pを逆に給電しないよう、待機中はデータ出力・バイアスとも解放する案。

まず実電源エッジを基準とした一回送信を試し、結果を見て送信時刻を比較する。
無制限の再送、GPIO直接5V制御、Flash書込みを追加しない。
ROMのLow応答が観測できた後に、SOFによるクロック校正とUSB引渡しを別に検証する。

ユーザーはスイッチ付きケーブルはないと回答し、RYKEN RK_M002 V1.5の写真を提示した。
DataとPowerの端子があり、VBUS分離が確認できれば使える可能性がある。
[無給電での導通確認](RYKEN_RK_M002.ja.md)を先に行い、既存回路への組込みはまだしない。

Data側のVBUS/VCCは全組合せ0.300Ωと実測確認され、主端子から分離できない。
Power側は基板が干渉するが、今回のData分離案には追加測定不要。
以下の2枚の緑基板による構成へ進む。

## 段階A: 5Vを接続しないデータ経路

PC・CM・T3Pをすべて電源から外して組む。
CMのオスを旧YC269のメスへ挿す。
新しいオス・メス基板は両USB端子を空け、2枚を次の短いジャンパ線だけで接続する。

| 旧YC269（CM側） | 新しい基板（将来のT3P側） |
| --- | --- |
| A1 GND | GND（SGNDではない） |
| A6 D+ | 既存CH2のD+測定点 |
| A7 D− | 既存CH1のD−測定点 |

5.098kΩのGPIO10→新基板D+経路と、両プローブ・GND接続は元の確認済み構成へ戻す。
VBUS/VCCは2枚の間でまだ接続しない。
電源OFFでGND同士の低抵抗と、旧A4 VBUS→新基板VCCの開放を確認する。
新VCCは写真の下段左から4番目（A4相当）を後の電源端子として選ぶ。
この検査が通れば、T3Pを外したままCMのメスだけをPCへ戻す。
既存v3のBIAS_CHECKでD+ジャンパ経路を、スコープ単独のBENCHでD−のデータ経路も確認する。
A/Bの接点が独立なので、CMプラグの向きによってA6/A7が非接続となる可能性はある。
その場合は通電を止めて向きを確認し、D+/D−を推測で入れ替えない。

段階B（電源ジャンパ、分圧・電源感知、T3Pへの接続）は段階Aの検査後。
現在のv3をそのまま無給電T3PへARMしても、電源エッジ基準の試験にはならない。

続いてユーザーがVCC/GNDに赤いジャンパを持つ青いUSB-Cオスメス基板を提示した。
この構造なら配線を減らせる可能性があるため、段階Aの緑基板3本配線は一旦保留。
まず[青基板のVCCジャンパと端子間の分離](BLUE_JUMPER_BREAKOUT.ja.md)を無給電で確認する。

青基板は左右黒取り出し基板のVBUS間でジャンパなしOL／ありほぼ0Ω、
GNDジャンパを残してGND導通を維持できるとユーザーが確認した。
この青基板を第一候補とし、無通電のデータ経路・短絡確認を依頼中。
まだCMやT3Pへ通電接続しない。電源感知ファームも未実装。

続いてUSB+／USB−経路各0.200Ω、両データ線間とVBUS-GND間OLをユーザーが確認。
CMのみ給電したVCCジャンパOFF時の先端側DC電圧測定を依頼したが、
ユーザーからオス／メスの区別について質問があった。まだ接続完了と判断せず、
PC接続は一旦待つよう案内した。
その後の写真でCMのBOOT/RST側（PC用）が青基板へつながっていた。
こちらの青基板左右のオス／メス案内は誤りだったため撤回。
CMのUSB-CM側プラグを基板列へ、BOOT/RST側の口をPCへ、という
CM自身の既知の端子位置を基準に組立を修正する。まだ電圧結果は得ていない。

## 電源検出のオフライン準備

`recovery/cm_rom_probe/power_gate.h` はまだmain.cへ組み込んでいない。
ADCの候補入力を前提に、100msの低電圧確認後だけ待機可能とし、
最初の立上りで試行を消費する。電源低下、明示解除、期限切れ後に自動再送しない。
候補閾値は10kΩ/10kΩ分圧、ADC基準3.3Vの仮定に基づくため、
実際の分圧電圧・ADC・スコープで照合するまで測定済みとはしない。
送信遅延はまだ試験値を選定していない。実ループのサンプリング間隔も未検証。
`tests/cm_power_gate.c` をホストclangの -Wall -Wextra -Werror でビルドし実行成功。
既給電での待機拒否、短いOFF期間、電源立上り・降下、期限境界、
一度だけの発火、解除後の再発火防止を検証した。
CMのUF2はビルド・書込みしておらず、v3動作は変更していない。

続報：別ソースの[電源エッジ補助プログラム](CM_POWER_PROBE.ja.md)を作成し、
ビルド、PC側操作条件9件、UF2形式4件を検証した。まだ未インストール。
実機は青基板OFF=0.000V／ON=5.085Vを確認し、10kΩ2本の分圧中点電圧を測定依頼中。
GPIO26への中点接続はまだ案内していない。T3Pは外したまま。
